# 第二阶段整体验收（ADV-10）

日期：2026-09-26。状态：通过。范围：MVP-01～25、ADV-01～10。基线提交：`2350107f51`（ADV-09）。源码指纹和逐项结果见[机器证据](evidence/adv-10-verification.json)。

## 验收对象和方法

测试环境运行本仓库固定 revision 的 Batfish、锁定 Pybatfish、FastAPI、独立 worker、隔离 PostgreSQL 与真实 Chromium；使用 r1/r2（华为/H3C）和 Cisco 四设备合成配置，不接入真实网络设备。新增的阶段样例在 Cisco 配置副本上同时添加孤立节点、c1→c2 的 BGP AS 错配，以及 c2 的 WEB-TEST/WEB-SEARCH 两组 ACL。原始配置位于仓库测试 fixture，派生内容由测试构造，不接触用户配置。

`tests/integration/test_advance_phase2.py` 对同一快照的三层拓扑边和 BGP 会话行直接调用公开 SDK 独立序列化后对照，核对孤立设备不会产生虚构边、AS 错配保持 `NOT_COMPATIBLE`，并在 Web API 中核对 ACL permit、显式 deny、隐式 deny、遮蔽和空匹配原因。登记式专家与专用 `nodes` 用相同请求命中同一有效参数和结果身份；未登记问题被 422 拒绝。此前 ADV-01～09 的独立 SDK 对照、华为/H3C 不支持范围拒绝、空结果及两用户不同快照测试继续包含在累计测试中。

`tests/advance-phase2.spec.ts` 从浏览器上传并初始化同一派生快照，依次查看拓扑孤立设备、BGP 模型错配、ACL 隐式拒绝和专家结果。每个结果都检查来源快照 ID；BGP 页面须明确“模型计算，非实时设备状态”。此前拓扑、BGP、ACL、专家页面及首版双用户浏览器用例继续参加完整回归。

## 结论边界

拓扑关系来自 SDK 推导边，孤立节点是“本次模型中无该类型边”，不能宣称物理断线。BGP 状态是配置模型计算，不能替代实时会话采集。ACL 测试只说明给定 ACL、设备及 Flow 的局部结果；隐式拒绝与无匹配/无示例不能解释为整网安全。华为/H3C 的未覆盖 ACL、IPv6 BGP 等限制依然按错误或警告展示，不记为验证通过。专家入口只有已登记且启用的能力，不开放任意 SDK 调用或主机/快照覆盖。

本报告检验 Web 链路和固定引擎在合成配置下的可追溯性，不验证 Java 核心与现场转发的一致性，也未取得百台设备容量证据。第三阶段以本篇累计门槛全部通过并单独提交为前置条件。
