# 产品设计与需求评估

## 目标与成功标准

建设中文 Batfish 分析工作台。用户通过创建网络、上传设备配置、检查解析质量、选择分析并阅读结果完成排障，不必理解 Notebook 或 SDK。首版成功标准是两名不同用户可在共享网络中分别发起任务，得到与相同参数 Pybatfish 调用一致且可追溯的设备、路由和单向虚拟 traceroute 结果。

## 对用户约束的评估

| 约束 | 判断 | 落实边界 |
| --- | --- | --- |
| api/service/controller 三层 | 合理 | api 校验传输格式并映射响应；service 校验业务状态/权限并编排；controller 操作 SDK，不把 controller 当 HTTP 入口 |
| 跨模块只通过 service | 合理 | 不允许跨模块访问 repository/controller；公共契约和基础设施可复用；模块依赖必须无环 |
| 最小必要参数 + kwargs | 合理，需要受控 | HTTP 使用有类型的 options；不能以任意字典代替契约；SDK 边界按白名单展开 kwargs |
| 简洁且支持专家 | 合理 | 基础与高级使用同一接口和状态模型，基础模式不隐藏已生效的高级参数 |
| 多级展示 | 合理 | 默认结论、展开证据、再查看原始结果；快照、覆盖限制、截断信息不能隐藏 |
| 完整适配 SDK | 分批覆盖公共能力更合理 | 先能力目录、后按业务场景适配；不把私有方法、连接配置或任意执行入口暴露成 API |
| 单 spec ≤2 人天 | 可作为拆分规则 | 按独立可验收增量拆分，包含测试和文档；技术未知先验证，禁止靠缩小验收范围满足预算 |

不强迫账号等不涉及 SDK 的模块建立空 controller；这些 service 直接使用本模块存储组件。持久化适配组件是实现支撑，不引入新的业务层。

## 使用场景与信息结构

网络是逻辑管理容器，快照是一份不可变配置状态。显示名用于界面，内部 UUID 用于定位；修改显示名不修改 SDK 名称。原始文件不在前端预先修剪、重写编码或清除终端控制字符，沿用引擎的厂商处理行为。

入口为网络列表。进入网络后顶部常驻快照选择和解析质量提示，左侧提供概览、设备、路由、连通性、任务；二阶段才显示拓扑、BGP、ACL，三阶段才显示变更对比和故障模拟。未启用能力不显示可点击的空页面。

基础流程：上传文件/ZIP → 校验输入 → 创建初始化任务 → 展示解析问题 → 加载设备信息 → 输入流量条件 → 查看路径和原因。解析不完整时允许检查配置和诊断；影响相关仿真的能力限制必须出现在结论附近。

## 三阶段范围

| 阶段 | 必须交付 | 明确不包含 |
| --- | --- | --- |
| 1 基础排障 | 登录/用户管理、网络/快照、上传、初始化诊断、设备/接口、路由/最长前缀匹配、IPv4 单向 traceroute、任务记录、结果导出、对应前端和部署 | 交互拓扑、BGP 专页、ACL 专页、快照对比、故障模拟、任意 SDK 控制台 |
| 2 日常排障增强 | 三层/协议拓扑、BGP 模型状态、ACL 流量测试与规则诊断、已登记问题的专家入口、联动前端 | 变更验证、自动修复、实时设备监控 |
| 3 变更验证 | 配置差异、路由差异、差异可达性、节点/接口故障派生快照、联动前端 | 向真实设备下发配置、自动审批、全组合故障搜索 |

IPv6、MPLS、SRv6、EVPN 是否可分析取决于当前厂商模型与问题能力。首版流量分析明确限定 IPv4；接口原始信息可展示已解析的其他地址，但不能据此启用未支持的转发仿真。

## 权限与协作

普通成员可创建网络、上传新快照、发起/查看/导出分析、取消自己尚未执行的任务。管理员增加用户管理、所有排队任务取消、删除资源和处理异常引擎占用的权限。全团队共享仍要求登录和服务端权限校验，不接受客户端传入的角色或发起人。

删除与在途任务互斥；快照不允许覆盖。已有历史结果在删除资源后保留带删除标记的来源信息，不可再据此重新执行。成员被停用后已有结果仍可查看，待执行任务在实际执行前重新检查发起人状态并失败退出。

## 关键交互

- 分析提交立即显示任务卡；页面刷新和离开不取消任务。
- 缺少必要参数时就地说明；SDK 拒绝表达式时保留用户输入并指出字段。
- “空表”表示没有匹配结果；“任务失败”表示无法得到结果；两者不得使用同一成功态。
- traceroute 按实际 flow 和路径分别展示；允许存在部分路径成功、部分失败。
- 只展示引擎实际返回的源文件/行号，不根据文本猜测对应配置位置。
- 专家查看原始结构化结果；页面不提供 Python 执行窗口。

## 模型边界

界面标注“基于快照模型”。BGP Established 是模型推演状态，不是设备实时状态；三层相邻关系不是物理布线证明；单向 traceroute 不能证明回程可达。当前 H3C/Huawei 存在仅提取或保留、不进入数据面的配置，PASSED 不能直接转成“所有功能验证通过”。
