## 需求与目标

用户可预览故障对象、创建派生快照并进入已限定范围的影响分析。

- 基线选择、节点/接口选择、方案预览、任务跟踪和比较入口。

## 设计与接口

- 仅使用 fault-scenarios 接口创建候选，准备完成后再通过 comparisons 创建上下文。
- 结果显示模型模拟，不提供对真实设备执行操作的入口。

沿用 api → service → controller；所有跨业务模块调用经过 service。非 SDK 存储由本模块 repository 负责。浏览器不接触 SDK 会话或连接参数。

## 测试与验收

- faults.test.tsx：双击不会重复派生快照。
- 失败/未知引擎状态不会显示为已模拟完成。
- 进入比较页方向固定且原基线选择保留。

前端组件测试在 `web/frontend` 下使用 `pnpm exec vitest run` 指定上述 `.test.tsx` 文件；页面交互同时按前端规范人工检查。

验收成功同时要求：契约与文档一致、失败行为可解释、无跨层/跨模块越界、没有把 mock 验证宣称为真实 SDK 验证。共享约束中的身份、版本、模型覆盖和结果截断规则均适用。

## 非目标与实施边界

- 不批量自动生成所有故障组合，不将模型结果解释为实时验证。
