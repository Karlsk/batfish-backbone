## 需求与目标

确认首版完整闭环达到验收标准，形成进入 advance 的依据。

- 真实引擎结果对照、两用户浏览器流程、权限/恢复回归、规模记录。

## 设计与接口

- 以 validation.md 的阶段 1 条目为准，缺少真实引擎证据不能通过。
- 产出验收报告包含版本、样本规模、性能数据、已知限制和通过/未通过结论。
- 发现超过本项预算的产品缺陷，拆新增修复 spec 后复验，不以备注替代失败条件。

沿用 api → service → controller；所有跨业务模块调用经过 service。非 SDK 存储由本模块 repository 负责。浏览器不接触 SDK 会话或连接参数。

## 测试与验收

- 跨快照内容和结果不串用；页面刷新可找回任务。
- 基础/高级相同有效参数得到同样分析结果。
- 解析不完整、不可达、空结果、失败、中断可区分。
- 只以实际测试规模报告容量，无样本不宣称100设备已达标。

后端测试在 `web/backend` 下使用 `uv run pytest` 指定上述测试文件；集成测试连接版本固定的隔离 Batfish 测试网络，不操作团队生产网络。

浏览器验收在 `web/frontend` 下使用 `pnpm exec playwright test e2e/mvp.spec.ts`；测试账号和快照应使用隔离环境。

验收成功同时要求：契约与文档一致、失败行为可解释、无跨层/跨模块越界、没有把 mock 验证宣称为真实 SDK 验证。共享约束中的身份、版本、模型覆盖和结果截断规则均适用。
