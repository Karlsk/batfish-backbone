# LDR-01 双入口与领导端壳层

- 状态：待开发；阶段：领导端；依赖：[ADV-18](../advance/adv-18-phase-three-acceptance.md)；预计 1.5 人天。
- 共享约束：[领导端设计](../../leader-design.md)、[前端规范](../../frontend.md)、[API 契约](../../api-contracts.md)。

## 需求与接口

现有技术路由及默认登录落点不变；新增 `/leader/overview` 等领导端路由的独立壳层和显式双向切换。全员使用原会话；浏览器偏好只记住用户主动选择的入口，未知/不可用存储回退技术端。主题、服务状态、退出和强制改密共用现有实现，切换不得重新提交任务或丢失历史结果。

前端路由仍在同一 Vite 应用；无后端变更。技术详情链接使用现有资源 ID，不透传 SDK 名称。领导页没有数据时使用明确空状态，不使用样例数字。

## 改动位置与步骤

- `web/frontend/src/app/`：将认证与共享 provider 保持在双壳层外，增加领导端布局、导航和路由入口；避免复制会话与主题状态。
- `web/frontend/src/features/leader/`：首个领导端概览占位仅提供结构、明确“尚未检查”和后续入口。
- 先写路由/主题/身份切换测试，再实现最小导航与响应式样式；覆盖桌面、键盘和减少动效。

## 验收

技术用户原路径与默认登录不变；管理员、成员均可切换并返回；主动偏好刷新后保留，损坏或禁用存储回退；切换时 Cookie/CSRF、网络快照、主题与已有结果不变。运行前端单测、`pnpm check:api`、`pnpm typecheck`、`pnpm build`、`pnpm format:check`，在真实 API 与 Chromium 中验证双主题入口和登录/改密/退出。不得把占位页写成完成的领导总览。

## 非目标与完成记录

不在本篇创建汇总 API、业务关注项或检查模板。完成后记录实际改动、测试数、环境版本与限制，更新阶段索引；未通过时保持待验证/未通过。
