# LDR-10 固定汇报与不可变事实接口

- 状态：待开发；阶段：领导端；依赖：[LDR-09](ldr-09-change-fault-ui.md)；预计 2.0 人天。
- 共享约束：[领导端设计](../../leader-design.md)、[架构](../../architecture.md)、[API 契约](../../api-contracts.md)。

## 需求与接口

`POST/GET /api/v1/leader/briefings` 与 `GET /{id}` 提供团队内固定汇报。创建最少为标题、网络、快照和已完成的 `result_ids`；可选比较 ID、业务关注项 ID/版本和明确标注的人工备注。服务端校验每项结果来源、有效范围、权限、状态与同网络关系，冻结系统事实、原结果引用、警告、截断、模型覆盖、Batfish/SDK 版本和时间。报告创建后系统事实不修改；改标题/备注生成新版本。成员可创建和读取，管理员可归档；不公开匿名链接。

来源网络/快照/结果后续删除时，冻结文字与 ID 保留，读接口附证据可读状态；不可用证据不伪装可跳转。任何业务关注项修改只影响新汇报，旧报告保留映射版本和内容。

## 改动位置与步骤

- `web/backend/app/modules/leader/`：briefing api/service/repository/DTO，迁移存不可变版本和归档；跨模块只调用已有 service，无 SDK controller。
- 先写跨网络/跨快照引用拒绝、警告冻结、版本修改、并发/幂等、资源删除后读取与双用户权限测试，再实现 OpenAPI。

## 验收

新分析、快照切换或映射修改不改变既有汇报；成员不能篡改系统事实；归档不抹去旧版本；打印数据不含敏感配置原文。目标/累计后端测试、Ruff、迁移、真实 API/PG 与 LDR-01～09 回归通过。
