# LDR-07 MVP 自主检查页面

- 状态：已完成；阶段：领导端；依赖：[LDR-06](ldr-06-check-runs-api.md)；预计 2.0 人天。
- 共享约束：[领导端设计](../../leader-design.md)、[前端规范](../../frontend.md)。

## 需求与接口

面向不写 Python 的用户，以“选网络与就绪快照 → 选问题 → 填最少范围 → 运行 → 看结论”完成配置质量、设备/接口、路由/LPM 与虚拟连通性检查。业务关注项可预填关键流量；用户仍需看清并确认当前快照与有效范围。高级条件折叠、保值并显示已启用数量。结果按结论/影响范围/证据/技术详情分层；路由、逐跳、原始配置与导出链接到现有页面。

查询与任务轮询消费 LDR-06 的运行记录，不在前端推断“全部可达”或复算 SDK 答案。离页再回可恢复，失败/中断/服务未就绪不伪装成功；排队取消遵循原任务规则。

## 改动位置与步骤

- `web/frontend/src/features/leader/checks/`：模板卡、范围表单、运行列表/详情和 MVP 结论适配器。
- 先写范围必填、业务映射预填、上下文切换、幂等双击、任务失败和结果来源测试，再实现；浏览器走两套合成配置。

## 验收

明确范围的 traceroute 展示模型条件与多路径/不可达区别；无结果为限定条件内空结果；配置质量警告在第一层。前端单测、API 类型/类型检查/构建/格式、真实浏览器与 LDR-01～06 累计回归通过。

### 2026-09-28 实施与验收

在同一前端项目新增 `/leader/checks` 和 `/leader/checks/:runId`，覆盖配置质量、设备、接口、路由、LPM 与单向虚拟连通性六个 MVP 模板。网络/就绪快照先选，路由前缀或连通性起点/目标必填；业务关注项可预填一条显式关键流量，手改范围清除映射绑定，切网清空旧快照与草稿。高级条件折叠保值。一次提交的幂等键在网络失败重试时保持；任务列表/详情通过持久 API 恢复，排队任务可依既有 job 规则取消。结果按结论、范围、证据/进度、技术详情分层，路径摘要只列已保存 disposition，覆盖/截断/模型限制与错误首层可见。
