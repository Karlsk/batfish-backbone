# 领导端双入口设计与公共契约

日期：2026-09-27。状态：已确认实施范围，LDR-01～12 按篇交付。前置证据：[MVP-25](mvp-acceptance.md)、[ADV-18](advance-phase3-acceptance.md)。本设计只用于 Web 产品，不改变 Batfish Java 引擎或声明现场仿真精度。

## 目标和信息层次

在现有 `web/frontend` 增加 `/leader/*`，现有技术路由保持不变。任何已登录的管理员或成员都能切换；原有登录默认进入技术工作台，浏览器可记住主动选择的入口。领导端由日常总览、网络与业务关注项、自主检查、变更与故障、固定汇报、全屏会议视图组成。复杂参数、原始字段和管理操作通过固定资源 ID 深链进入技术端。日常页强调可读性，会议页放大事实与图；沿用深浅主题、键盘焦点和减少动效偏好。

展示顺序固定为“结论 → 影响范围 → 证据 → 技术详情”。每一条结论必须绑定网络、快照或比较 ID、有效分析范围、结果 ID、版本与生成时间。空结果、未检查、失败、中断、未知状态、模型限制和截断分别呈现；完成任务不等于网络健康。不存在可证明的业务映射或分析结果时不生成业务影响、总体健康分或虚构计数。历史结果仍绑定运行时快照，切换顶部上下文不改写它。

## MVP/ADV 覆盖映射

| 已交付能力 | 领导端第一层 | 进一步操作 |
| --- | --- | --- |
| 身份、网络、快照、上传、诊断、任务、导出、删除（MVP） | 总览显示有来源的网络/就绪快照/质量/任务状态；检查入口显示输入准备情况 | 上传、配置行、原始结果、导出与管理员删除跳技术端 |
| 设备、接口、路由、LPM、虚拟路径（MVP） | 自主检查显示限定网络和范围下的设备/路由/路径结论 | 路由行、逐跳、LPM 高级参数跳技术端 |
| 拓扑、BGP、ACL、专家能力（ADV-01～10） | 业务关注项网络图、会话与规则检查结论；专家能力只展示登记项 | 交互拓扑、BGP 会话、ACL 证据和专家查询跳技术端 |
| 配置/路由/可达性差异、故障派生（ADV-11～18） | 固定基线/候选、变化方向、故障方案和受影响的明确范围 | 文件行、路由行、双侧 trace、派生诊断跳技术端 |

## 后端模块与接口

保留 `api → service → controller → SDK`。新增领导端模块只做已存事实的读模型、检查编排及汇报冻结；跨模块只调用 network、snapshot、analysis、changes、jobs、results 等 service，不能直接调用它们的 repository/controller。无直接 SDK 需求的新增模块不创建空 controller。所有写请求沿用 Cookie、Origin、CSRF 与现有审计/幂等模式。

1. `business-concerns`：`GET/POST /api/v1/business-concerns`、`GET/PATCH /api/v1/business-concerns/{id}`。`POST` 最少包含 `name`、`network_id`、`priority` 与 1～10 条 `flows`；每条 flow 必填起点和目的 IPv4，协议/源地址/目的端口为已校验的可选项。管理员可创建、修改或归档；成员可读。修改生成单调递增版本，旧汇报保留当时完整映射。业务关注项以网络为归属，执行时再绑定具体就绪快照，不从设备名推断业务关系。
2. `leader/overview`：`GET /api/v1/leader/overview?offset&limit` 返回全部共享网络的有界分页卡片和明确口径的汇总数。每个网络取最新**就绪**快照（时间并列用 ID 稳定排序），同时返回最新快照是否未就绪；没有就绪版本就标“待准备”。只展示可证明的解析质量、最近检查状态、覆盖/截断提示。总数不从单页去重推断。
3. `leader/check-runs`：`POST/GET /api/v1/leader/check-runs` 和 `GET /{id}`。请求最少为 `template_id`、`network_id`、`snapshot_id`；需要范围的模板额外使用有类型 `scope`，专家选项仅通过既有白名单。`Idempotency-Key` 避免重复创建。服务端按模板调用现有 service 提交一个或多个持久 job，不在 HTTP 进程执行 SDK 工作；运行记录冻结模板版本、有效参数、job/result ID、状态和错误。未知引擎状态不重放；失败由用户显式发起新运行。
4. `leader/briefings`：`POST/GET /api/v1/leader/briefings` 和 `GET /{id}`。请求最少为 `title`、`network_id`、`snapshot_id`、选定的 `result_ids`，可带 `comparison_id` 与 `notes`。服务端验证所有来源同网络/快照或固定比较对、权限与结果终态；冻结标题、人工备注、业务关注项版本、有效范围、系统结论、警告、版本、生成时间与来源 ID。系统事实不可编辑；修改标题或备注也生成新版本。资源后续删除时保留冻结内容，证据深链不可读取时显示“来源已不可用”。团队内登录用户可读和创建，管理员可归档；不提供公开分享。

模板分两类：配置质量、设备清单、拓扑和 BGP 等可由就绪快照运行；连通性、ACL、路由/LPM、变更、故障必须先选择业务关注项或明确填写必要范围。任何模板不得自行推断目的地址、协议、受影响业务或自动穷举全部故障组合。路由和可达性变化沿用固定“基线左、候选右”。

## 前端流程与异常

- 入口：技术端顶部显式“领导视图”；领导端提供“技术工作台”。同一会话与 QueryClient，切换不清理身份或改写历史结果。偏好只保存显示入口，不保存 token、引擎地址或业务配置。
- 日常总览：跨网络分页、质量/最近检查/业务关注项，点击进入单网络证据。无结果为“未检查”；有警告、覆盖有限、截断在第一层可见。
- 自主检查：先选网络和就绪快照，再选可运行模板；要求范围的步骤给出业务关注项预填并允许显式调整。提交后可离开页面，回来通过检查记录继续查看任务；排队取消和失败恢复遵循原任务语义。
- 变更/故障：选择两份同网络就绪快照或一份故障基线，预览不可变关系，只有显式选定范围才显示范围内结论。派生失败、未知占用和解析警告不得表现为成功。
- 固定汇报：可选择已完成的结果组成章节，页面把系统事实与人工备注分开。会议视图只读全屏、适度动效、支持 `prefers-reduced-motion`、打印 CSS 和浏览器另存 PDF；打印包含范围、时间、版本和限制。

## 验收约束

每篇有本篇测试和此前 LDR 累计回归。LDR-12 使用固定 Batfish revision、PostgreSQL、API、worker、r1/r2 与 Cisco 四设备和双用户浏览器，跑 MVP/ADV 原有门槛、生产构建明暗主题与 HTTPS 恢复。真实配置与现场设备精度不在范围。之前截图中的 `NOT_READY` 已在当前已就绪 Cisco 快照上复测成功，但原请求上下文缺失；真实浏览器检查要覆盖未就绪快照/服务并给出可行动的错误说明，不能隐藏错误。
