# ADV-06 ACL 页面实施计划

目标：让技术工作台用户基于已选快照，以最小字段验证某条流量在指定 ACL 下的局部动作；高级参数和原始证据按需展开。

1. 在 `web/frontend/src/features/acl/requests.ts` 建立草稿与严格请求转换；`filter-test.test.tsx` 先证明 IPv4、节点/ACL、协议/端口约束及折叠值保持，观察失败后实现。
2. 在 `FilterTest.tsx` 使用当前快照加载设备候选，并通过已登记 `resolve-filters` 任务取得 ACL 名称；选择值与网络/快照绑定，手输仅用于专家表达式。提交 `test-filters` 后进入任务页，保留幂等重试语义。组件测试先覆盖候选与错误、默认/高级提交。
3. 在 `FilterResult.tsx` 读取固定结果的分页行；首层显示 PERMIT、DENY、无匹配或模型不支持，详情显示 `Line_Content`、Flow、来源引用及原始 Trace。隐式拒绝不产生规则号或虚假来源。通过固定上下文恢复后跳转 traceroute，预填源/目的/协议/端口，但起点保持空白。组件测试先覆盖上述状态。
4. 在 `App.tsx`、`Results.tsx` 接入入口和专用结果；在 `TraceForm.tsx` 安全读取同快照预填状态。目标测试通过后运行完整前端/后端、真实双拓扑浏览器、HTTPS恢复与双主题双用户累计验收；回写 spec/索引/证据，逐篇提交。

自审重点：上下文切换时旧候选不污染新页面；服务端拒绝的厂商不展示绿色结论；无匹配不是放行；ACL 局部动作不等同端到端可达；幂等键仅重试同一次请求。
