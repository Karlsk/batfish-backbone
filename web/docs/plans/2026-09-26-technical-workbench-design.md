# 技术工作台双主题视觉升级设计

日期：2026-09-26。

状态：技术工作台双主题已实施并完成真实环境验证；焦点环余项已在后续MVP复验修复，见[验收记录](../evidence/technical-workbench-theme-2026-09-26.md)。未提交 Git，ADV 与领导端暂不实施。

## 1. 已确认的目标与顺序

先升级现有技术工作台的视觉，再完成 ADV-01～18，最后针对领导的日常总览、会议展示、自主检查建设独立体验。本次使用现有 `web/frontend`，不另建前端项目，不增加领导模式。

早期“现有前端不动”的方向已经被“先改现有技术页面风格”取代。产品实现已按后续确认应用到现有前端；早期样板保留作设计参考。

目标是更有质感和科技感，同时让技术人员能长时间阅读配置、路由和路径证据。保持现有操作流程、接口契约、权限、上下文隔离和结果语义。没有得到产品实施指令前，不把视觉确认当成实施或启动 ADV 的授权。

## 2. 样板与适用边界

已确认的参考：[路由页深浅双主题交互样板](../prototypes/technical-workbench-dual-theme-v1.html)。可直接在浏览器打开，支持主题切换、查询/结果页面切换、高级参数、模拟执行、结果筛选和详情抽屉。

样板仅作视觉参考，全部是明确标注的静态示例；导航占位、执行动画、导出样例不能代替真实产品实现或验收。正式应用移除设计预览工具栏及示例标识，保留真实数据来源和模型边界提示。

认可的是整体视觉、层次和渐进交互。样板中的八条路由、四台设备、0.41秒、业务名称、快照名称不是正式页面的默认值，不能原样移入应用。

## 3. 双主题视觉体系

两种主题共用组件结构、路由和状态，只切换语义颜色及相关表现。禁止复制两套页面分别维护。

| 语义 | 浅色 | 深色 |
| --- | --- | --- |
| 工作区背景 | 冷灰 `#eff3f9` | 深蓝黑 `#0a111e` |
| 内容面板 | 白色 `#ffffff` | 蓝灰 `#111d2e` |
| 次级面板 | `#f6f8fc` | `#162438` |
| 主文字 | `#1d2a42` | `#e6edf9` |
| 次级文字 | `#65768f` | `#93a6c1` |
| 边框 | `#d9e1ed` | `#27364c` |
| 强调文字 | 蓝色 `#3e57d9` | 浅蓝 `#91a6ff` |
| 协议/辅助强调 | 青色 `#007e85` | 青色 `#6addd8` |
| 主要操作 | 蓝紫实色按钮；文字对比度需实测 | 同一语义，匹配深色背景 |
| 导航侧栏 | 深蓝背景 | 深蓝背景，与内容区分层 |

以上为样板参考值。实际组件组合如未达到下述对比度要求，可微调具体色值，不能为了完全复制样板而牺牲可读性。

字号以正式应用现有14px正文为基准，表格及代码不低于12px；不机械复制样板中小尺寸的装饰文字。标题约24～28px，采用系统中文字体，IP、前缀、编号和原始字段使用等宽字体。间距以8px为基础，面板圆角约8～12px。

科技感主要来自导航层次、选中强调、协议标签、线条和短动效。数据表格与原始配置保持清晰，不用持续闪烁、背景粒子或装饰性数字占用注意力。未来拓扑、路径动画只表达真实交互和计算状态。

## 4. 主题行为

- 提供“浅色 / 深色 / 跟随系统”，默认跟随系统；用户显式选择优先。
- 作为本机浏览器的显示偏好持久化，不新增用户资料接口；不是账号权限或业务数据，不要求跨设备同步。
- 登录、首次改密、退出后页面和工作台遵循同一选择；退出清理业务缓存时不必清除主题偏好。
- 仅在“跟随系统”时响应操作系统主题变化。浏览器存储被禁用或值不合法时回退到跟随系统，不能阻止登录或页面渲染。
- 首屏使用与应用一致的主题解析规则，避免刷新时先闪白再变暗。主题切换不得重新创建 QueryClient、清理表单、切换快照、重新提交任务或导致页面重新挂载。
- 下拉菜单、抽屉、弹窗、消息提示等浮层跟随主题。关注挂载到 body 的浮层，不能出现深色页面中残留的浅色块。

## 5. 页面与组件覆盖

### 工作台外壳

保留概览、网络与快照、网络分析、任务中心和管理员用户管理入口。升级品牌区域、导航选中态、顶部网络/快照选择、账号入口和服务就绪显示。网络分析子入口沿用实际存在的路由，不展示未实现的 ADV 按钮。

标题区统一为当前位置、主标题、简短说明和主要操作。上下文选择仍控制后续操作，历史任务/结果保留自己的来源信息。权限依然由后端校验，样式调整不改变成员可见或可执行的功能。

### 查询与结果

路由页作为首个落地样板，再推广到设备、接口、LPM 和 traceroute。默认显示必要参数；高级参数折叠后保留值、显示生效数量。实际支持的字段、枚举、输入方式取自现有契约，不从样板选项反推 API。

保留“提交查询 → 任务详情 → 查看固定结果”的流程，不把样板的模拟自动跳转当成新业务行为。允许优化已有入口的排布，不合并查询状态和历史结果上下文。

结果按摘要、证据表格/路径、来源与有效条件、原始详情分层。宽屏将来源/条件放在右侧，较窄时移到表格后方。表格支持现有分页、筛选、关键/全部列、详情和导出；详情抽屉保留稳定的资源身份。

摘要只使用已有可信数据：

- 行数来自结果摘要或分页总量，不从当前页推断全量。
- 有名称可显示名称，同时保留ID；历史资源已删除或名称不可读取时仍用固定ID说明来源。
- 设备数没有可靠汇总时不展示，不能对当前分页去重后称为总设备数。
- 耗时只有可靠的任务关联与起止时间时才显示，并标明测量含义；没有数据时省略，不为视觉填充虚构数字。
- 不能借“参数摘要”发起额外 SDK 计算；从已有任务/结果 DTO 取值。

覆盖不足、解析异常、ignore_filters、截断和未知占用仍在第一层可见。“查询完成”只是执行状态，不等于网络健康、现场可达或模型覆盖完整。

### 其他已实现页面

登录、改密、用户管理、概览、上传向导、网络/快照列表、初始化诊断、原始配置、任务中心、删除确认及恢复对账全部纳入主题适配。配置行号、高亮行、长名称、错误详情、空结果和加载状态必须在两种主题下可读。

## 6. 实现边界与组织

沿用 React、TypeScript、Vite、Ant Design、TanStack Query 和既有锁文件，不为换肤引入新的 UI 框架或整套动画库。

预期集中管理主题偏好、语义 token 与 CSS 变量；Ant Design 的组件主题与自定义 CSS 使用同一来源。由现有 Providers 接入主题，不影响身份切换后的业务缓存清理。壳层、共用组件和页面逐步迁移，不能仅给 body 增加暗色背景。

本次不改后端 API、SDK controller、任务调度、数据库或结果格式。若真实数据不足以实现某个装饰性摘要，优先省略；确需新增业务能力时另列规格，不能夹带后端改造。

在正式实施时同步修订 [前端规范](../frontend.md) 的“浅色工作台”描述为本设计的双主题规则；其余渐进展示、权限、模型边界和数据来源原则继续有效。前端规范已同步本轮双主题实现。

后续 ADV-01～18 继续在当前技术产品上实现，其中 ADV-02 的技术拓扑仍位于现有前端；前一讨论中迁移到新领导前端的建议不再采用。新页面必须复用本轮主题体系。领导端的业务映射、检查模板和汇报结构另行设计。

## 7. 验收标准

### 视觉与可访问性

- 在1280、1440、1920宽度检查深浅主题；主要操作不被遮挡。较窄视口可让表格横向滚动，不强求缩小所有文字来塞进一屏。
- 普通文字与背景对比度以4.5:1为验收目标，必要控件边界与焦点指示以3:1为目标；逐项实测，本文不宣称样板已经满足。
- 状态同时提供文字或图标，不能只靠红绿表达。键盘可操作主题切换、表单、抽屉和弹窗，关闭后焦点返回触发位置。
- 动效短且适度，遵守 prefers-reduced-motion；加载、空结果、失败、中断、权限不足与成功分别检查。
- 保留对网络分析状态和模型限制的真实描述，不增加“健康分”等缺乏依据的结论。

### 行为回归

- 主题初始解析、合法/损坏偏好、存储不可用、系统变化、刷新保持使用有意义的测试覆盖，不为每个颜色写镜像式单测。
- 填好高级参数后切换主题、折叠/展开、打开详情，值和上下文保持；切换主题不能额外提交查询。
- 运行前端现有 test、check:api、build、format:check 和浏览器回归。保留登录、用户管理、上传初始化、任务取消/重试、结果来源、诊断、路径与导出行为。
- 两种主题均在真实 API/worker/PostgreSQL/Batfish 和 r1/r2、Cisco 四设备配置上走代表性闭环。双用户独立上下文、角色限制与撤销会话仍须成立。
- 最终验证生产构建的主题持久化、浮层及双用户场景；后端未变更时复用已核对身份的服务，不为视觉改造重跑 Java 全量测试。
- 已完成的 MVP 历史证据保持原样；本次建立自己的实施、视觉与回归记录，不把旧通过结果写成本轮验证。
