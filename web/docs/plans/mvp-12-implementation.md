# MVP-12 实施计划

1. 测试先行：能力登记/阶段开关/未知options、嵌套Flow/Trace/集合/NaN、稳定分页和输出上限、缓存版本和身份隔离、发布回滚与中断竞争。
2. 建立公共能力及结构化结果DTO，controller只使用登记问题；service进行参数校验、可用快照校验、质量来源附着和缓存键生成。
3. results保存不可变文件、元数据和缓存键。通过公共service与共享事务把结果发布和job成功一起提交，租约或未知占用变化时禁止发布；发布文件后数据库结果不确定时保留可核对文件。
4. execution handler增加结果发布阶段，在完成SDK及预算/占用检查后执行事务发布；保留现有只返回UUID/None的handler兼容性及所有恢复门槛。
5. GET capabilities及结果元数据/表格行/flow/trace分页；校验筛选和排序列，限定行/字节数并展示截断。缓存命中仍新建当前用户job。
6. 本篇目录登记后续能力但保持未交付项disabled，具体网络查询在MVP-13～15启用；测试使用明确测试handler与真实SDK结果验证标准化，不宣称产品业务已交付。
7. 独立只读审查，真实两套拓扑与API累计验收，回写证据并提交。

共享契约边界：跨模块仅service；SDK对象仅controller转换；结果文件上限100MiB、表格100000行是可调整设计值，不代表引擎内存或压测容量保证。
